## Findings that determine the plan

- **Managed binding already has a native service.** [ManagedAssets](../../src/runtime/managed-assets.ts) verifies references against the active Cavern/session and manages runtime URLs, integrity checks and disposal. A syntactically valid hash/reference is not authority. Resolve references from current authorized source Blocks; do not accept model-provided asset/Cavern IDs.
- **Retained captures have domain factories, not a universal trust check.** PDF/IIIF/web/academic factories consume host capture objects; some validate shape, while PDF/IIIF constructors assume their caller supplied trusted snapshots. Resolve snapshots through native retained-resource services, verify domain identity and original dependencies, then call the existing factory. Copying a capture-shaped JSON object from model output cannot establish provenance.
- **External references and acquisition are different operations.** [resourceUrl/resourceBlock](../../src/interchange/resource-url.ts) and [inspectUri/passiveVideo](../../src/interchange/uri.ts) provide explicit native routes. The explicit image-resource route requires downloaded/validated managed image data; the older Add Image URL route has a different policy. Share and describe each qualified route rather than silently equating them. Existing YouTube authoring stays compatible.
- **Native fragments are the necessary admission boundary.** DCP currently prepares DTO children; resource factories and [captureBlocks/cloneBlocks](../../src/block-tree/clipboard.ts) produce canonical `BlockFragment`s. Passing clones through DTO or inspection reconstruction would lose information. Extend the existing contribution transaction to admit host-prepared fragments with `insertFragment`, alongside its authored composition, definitions and source annotations. Keep this internal; no new wire-level Block system or resource registry.
- **Native copying has deliberate limits.** Contribution/conversation wrappers are rejected. Scoped Entity references and argument-linked passages can be rejected because semantic dependency remapping is incomplete. Preserve these checks; a shared native extension requires its own review, not a DCP bypass. Capture currently also scans source contents for retained Document definitions; qualify a bounded non-Document capture path before exposing subtree copying.
- **Rollback has two boundaries.** Native Document admission can be atomic. Asset publication and canonical resource capture can precede it and survive cancellation. The current asset ledger retains published objects even on abort; Undo removes an occurrence, not its retained original. Do not promise distributed rollback or introduce new garbage collection.

## Authority, reading and catalogue rules

**Revised authority boundary:** AI participation authorizes ordinary supported external URL references and embeds through enabled capabilities. Existing-source handles are required for binding, copying or annotating native content, not for introducing a new external URL. Reference, browser embed and retained acquisition are distinct operations. Do not add conversational permission barriers; do not bypass the actual native acquisition requirements.

Keep purpose-driven constructs. Illustrative candidates are an image with an authorized `source` handle, a validated video/embed URL, and `copy {id,kind,source,revision}`. Final field names belong to each increment's reviewed schema. Models never supply native DTOs, captures, provenance, hashes, retained snapshot IDs, owner IDs or lease tokens.

Initial binding/copying stays within committed sources in the current Document. An issued handle authorizes only the resolved source and the native dependency closure required by that operation. It does not authorize vault enumeration, arbitrary other-Document reads or dereferencing terminal foreign references. Resources outside this context need a separately qualified native user-selection/context route; this is a missing prerequisite, not intrinsic resource unauthorability.

Resolve resources host-side, fence the source and relevant native dependencies, verify current resource/session state, prepare without modifying the source, then recheck immediately before a single canonical contribution commit. Aborts and feature removal discard preparation and release temporary resources. Bound capture before allocation, count generated descendants/Cells/definitions, and keep discovery, verification, snapshots and acquisition off the typing path.

Inspection provides native handles, relationships, resource kind and bounded readiness diagnostics; it never serves as clone input. Catalogue detail distinguishes **binding**, **external reference**, **acquisition**, unavailable prerequisites and unsupported native operations. Keep concise initial summaries and bounded detailed discovery. Media generation remains outside scope.

Resource viewers require the same Stage 2 state audit. PDF/IIIF/academic views contain annotation, extraction or configuration actions that can mutate authored records; ordinary viewing is not blanket permission for those actions inside submitted content. Retain safe local presentation, guard unsupported authored/operational changes and report limitations. Do not relax submitted-content protection.

## Small live exercise and deterministic baseline

One isolated real OpenAI exchange used the repository's default `gpt-5.4-mini` model (8,192 output-token limit; standard single repair enabled), existing broker, provider schemas/tools and native controller admission. It used synthetic content, disabled continuity, and touched no user Document or Cavern. Broker diagnostics were enabled and inspected; the retained [exercise summary](DCP_STAGE3_PLANNING_LIVE_EXERCISE.json) contains receipts, tool names, native effects and diagnostic counts.

**Partial success:** the model called `list_text_blocks`, then `read_source`, and committed a paragraph, structured list, tabs and timer. It created a native anchor for “green patina” in the earlier source, but the requested highlight was absent on that source. Three provider turns completed with no validation error or repair. An anchor alone is not counted as the requested applied annotation. The retained summary does not establish the omission's root cause; preserve this as a focused follow-up before calling the live exercise fully qualified. Investigate the raw response and native interpretation path in that follow-up, without adding task-expectation enforcement or changing validation. This observation does not reopen the accepted Stage 2 architecture or justify a broad benchmark.

The temporary exercise harness was removed. No Stage 3 code was introduced. **56 existing deterministic tests passed** across managed assets, clipboard images, explicit resource URLs, native clipboard copying, native resource persistence, and IIIF/web/academic persistence:

```sh
npx vitest run src/runtime/managed-assets.test.ts src/interchange/clipboard-images.test.ts src/interchange/resource-url.test.ts src/runtime/block-clipboard.test.ts src/persistence/native-resource.test.ts src/iiif/persistence.test.ts src/web-resources/persistence.test.ts src/academic/persistence.test.ts
```

These establish a reuse baseline, not qualification of unimplemented DCP resource routes. Reuse them plus existing Dialectic fixtures for each increment; include provider-schema compatibility and bounded-work checks. Manual Document saving remains unchanged.

## Carried-forward gaps and stopping point

The completed Stage 2 plan does not imply universal parity. Carry forward horizontal rules, legacy plain-code Blocks, standalone checkboxes, existing-container sticky tabs, legacy book-dependent pages, workspace Canvas counters, Phosphor host sessions and other canonical-audit context gaps. Keep host-only operations out of ordinary contributions. Native cloning must not become a means to smuggle unsupported host authority or silently drop dependencies.

Review requested: the 3A → 3B → 3C → 3D → 3E sequence, the host-private fragment boundary, same-Document initial authority and separate acquisition side effects. Stages 3A/3B are accepted. Stage 3C.1 PDF binding is implemented; the remaining retained-family subincrements are identified in its qualification report. Stage 3D has not begun. Generation, Markdown fallback, notices, task-expectation enforcement and general retroactive editing remain deferred.
