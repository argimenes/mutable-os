# Stage 2 — native composition, configuration and curated standoff authoring

Stages 1 and 2A–2D are accepted. The planned Stage 2 increments are complete. Continue the native model → shared preparations → concise DCP projections architecture. Deliver each family separately; do not begin Stage 3 automatically.

| Increment | Scope and native operations | Qualification gate |
| --- | --- | --- |
| **2A — Text authoring (accepted)** | Shared text appearance preparation for alignment, indentation and named text sizes; extend paragraph/heading with nullable `textStyle`. Native literal `code` and `source` projections reuse/extract code/source factories. Curate strikethrough, subscript, superscript, fixed highlighting, background colour and hyperlinks beside their native style descriptors. Inline/range/existing-source paths share preparation. Extend inspection for literal content/configuration; guard code/source controls in immutable contributions. | Human/DCP native equivalence; literal preservation, schema/parameter validation, source authority, rollback, Undo/Redo, native save/reload, disabled-feature compatibility, bounded typing work. Provider schema fixtures; one live exchange only if credentials are available without disrupting user Documents. |
| **2B — Lists and layouts (accepted)** | Ordered/bullet/task list configuration; initial task completion; supported native table/grid configuration. Share existing list/task/table preparation rather than rebuild their hierarchies. | Ownership and layout constraints, native equivalent output, protected checkbox controls, invalid configuration rollback. |
| **2C — Compound Documents (accepted)** | Surfaces/Sides, labelled tabs/orientation, pages and marginal content. Builders own internal shells and named relationships. | Native ownership/relations, meaningful inspection, protected navigation versus authored changes, no flattening or reconstruction claims. |
| **2D — Notes and widgets (accepted)** | Sticky notes and applicable Document widgets; reuse widget models and setting validators. | Authored initial state versus operational/presentation state, immutable submitted content, lifecycle/cleanup and persistence. |

2A is a bounded text-family increment, not completion of Stage 2. The legacy `Add Code` route (`code-mirror-block`, currently a textarea preview) still needs a shared plain-code preparation and separate control qualification; the standoff-code projection does not claim that operation. Keep it in the remaining Stage 2 inventory. Existing paragraph/group/list/table/heading/grid/YouTube forms, typed aliases, exchange-local source authority, provider continuity and canonical atomic commit remain. Later families are explicit deferrals against the canonical inventory; internal rows/cells/Sides do not require separate authoring constructs.

`textStyle` is a nullable object with nullable `alignment`, `indent` and `size` fields; null means native default/no property. Sizes are `normal`, `half`, `three-quarters`. Heading level remains the single heading-size representation, so a heading cannot also specify text size. The strict negotiated provider schema requires `textStyle` for paragraph/heading; host admission continues accepting the existing omitted-field form. No generic property mutation channel or metadata DTO is introduced.

`code {id,kind,language,text}` creates native standoff code with an owned TextBlock. `source {id,kind,format,text}` retains exact Markdown/HTML in the existing source Block with its versioned payload; it does not convert Markdown to composition or implement Surface-backed fallback. Unsupported highlighting languages remain literal code and are described accordingly. Source previews retain native isolation; no acquisition or executable HTML authoring is added.

Feature `dcpNativeAuthoringStage2Text` gates this extension and depends on Stage 1. It was disabled during qualification and is enabled after the 2A gate passed. Catalogue detail derives schemas/native effects from the shared preparations and curated descriptors, within existing discovery budgets. Preserve baseline and Stage 1 modes when disabled. No full registry is injected into requests.

Deferred throughout: Surface-backed Markdown fallback, notices/activity, task-expectation enforcement, broad acquisition/generation, raw DTO authoring, and general editing of immutable submitted content. Reading remains bounded and explicitly non-lossless; native copying and resource binding belong to later work.
